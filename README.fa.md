# iran-idcard-ocr

تشخیص کارت، تصحیح پرسپکتیو و OCR برای **کارت ملی ایران** (قدیم و جدید، رو و پشت) فقط با CPU، همراه با **نگهداری رمزنگاری‌شده‌ی تصویر کارت** برای احراز هویت بعدی.

[English](README.md) · [معماری](docs/architecture.md) · [API](docs/api.md) · [عملیات](docs/operations.md) · [کالیبراسیون روی کارت واقعی](docs/calibration.md) · [بنچمارک](docs/benchmarks.md) · [حریم خصوصی و امنیت](docs/privacy-and-security.md)

> **قبل از هر چیز؛ وضعیت و محدودیت‌ها (صادقانه)**
>
> * لِی‌اوت‌های داخل پروژه برای **کارت‌های نمونه‌ی مصنوعی** است، نه طرح واقعی کارت. دقت روی کارت واقعی **اندازه‌گیری نشده**. قبل از استفاده‌ی واقعی باید لی‌اوت‌ها را با `idcard-ocr overlay` کالیبره کنید ([راهنما](docs/calibration.md)) و بنچمارک را روی نمونه‌های واقعیِ با رضایت کاربر اجرا کنید.
> * اولین اندازه‌گیری روی عکس واقعی (کارت‌های ساختگی از دیتاست کگل، فقط روی کارت جدید، ۴۰۰ عکس دستیِ کنار گذاشته‌شده برای ارزیابی): ۸۸٪ عکس‌ها پذیرفته می‌شوند؛ دقت روی همه‌ی عکس‌ها: با خواننده‌ی خطیِ اختیاری ([docs/crnn.md](docs/crnn.md)، مدل منتشر نمی‌شود): F1 کد ملی ≈۷۲٪ (precision ۹۹٫۶٪) و تاریخ‌ها ≈۷۰٪ (precision ≈۹۸٪)؛ نام‌ها ≈۲۵٪ و همیشه برای بازبینی. بدون آن: کد ملی ≈۴۲٪، تاریخ‌ها ≈۳۴٪. این هنوز کیفیت تولید نیست ([بنچمارک](docs/benchmarks.md)). برای پشت کارت و کارت قدیمی کالیبراسیون واقعی وجود ندارد.
> * مدل ارقام پیش‌فرض روی فونت آموزش دیده و ارقام کارت واقعی را نمی‌خواند؛ مدل آموزش‌دیده روی گلیف‌های واقعی می‌خواند ([calibration/kaggle](calibration/kaggle/README.md)).
> * خواندن نام‌ها با Tesseract فارسی ضعیف است؛ **نام‌ها همیشه `needs_review: true` هستند** و باید کاربر تأیید کند.
> * این پروژه فقط OCR است: تشخیص زنده‌بودن، تطبیق چهره، تشخیص جعل و استعلام ثبت احوال ندارد. خروجی را برای پیش‌پر کردن فرم به کار ببرید، نه به‌عنوان احراز هویت کامل.

## امکانات

* پیدا کردن کارت در عکس موبایل، اصلاح پرسپکتیو، تشخیص وارونگی.
* تشخیص **رو/پشت** و **قدیم/جدید**.
* رد عکس‌های نامناسب با دلیل مشخص (`blurry`, `too_dark`, `glare`, `low_resolution`) تا کاربر دوباره عکس بگیرد.
* خواندن هر فیلد از ناحیه‌ی مشخصش: کد ملی، نام، نام خانوادگی، نام پدر، تاریخ تولد، تاریخ انقضا، سریال پشت کارت.
* اعتبارسنجی: **چک‌سام کد ملی**، تاریخ شمسی معتبر (با تبدیل به میلادی)، الگوی سریال.
* هر فیلد مشکوک با `needs_review` و فهرست `issues` علامت می‌خورد؛ حدس بی‌صدا نمی‌زند.
* تصویر اصلی و کارت اصلاح‌شده با **AES-256-GCM** رمزنگاری، با زمان نگهداری، چرخش کلید و حذف.

## چرا این طراحی (منابع محدود)

بدون GPU و بدون فریم‌ورک یادگیری عمیق؛ حدود ۰٫۳ ثانیه برای هر تصویر روی یک هسته در بنچمارک مصنوعی. همزمانی محدود است تا سرور کوچک از پا نیفتد. ارقام با یک طبقه‌بند سبک (HOG + k-NN، حدود ۱ مگابایت) و رمزگشایی هدایت‌شده با چک‌سام خوانده می‌شوند؛ نام‌ها با Tesseract.

## شروع سریع

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-fas tesseract-ocr-ara tesseract-ocr-eng fonts-dejavu-core
pip install .

idcard-ocr synth --out data/demo --count 8 --difficulty easy
idcard-ocr extract "$(ls data/demo/*.jpg | head -1)"
idcard-ocr bench data/demo
```

سرویس HTTP:

```bash
cp .env.example .env     # IDCARD_API_KEYS و IDCARD_STORE_KEYS را تنظیم کنید (idcard-ocr gen-key)
docker compose up --build
curl -H "X-API-Key: $KEY" -F file=@card.jpg -F store_image=true http://127.0.0.1:8000/v1/extract
```

بدون کلید API سرویس بالا نمی‌آید (مگر با `IDCARD_ALLOW_ANONYMOUS=1` فقط برای توسعه).

## نتایج بنچمارک مصنوعی

| معیار | easy | medium | hard |
|---|---|---|---|
| کد ملی دقیق | ۱۰۰٪ | ۸۹٫۷٪ | ۶۴٫۳٪ |
| تاریخ تولد دقیق | ۱۰۰٪ | ۸۶٫۲٪ | ۶۴٫۳٪ |
| خطای بی‌صدا (غلط و بدون علامت) | ≈۰٫۵٪ | ≈۱٫۱٪ | ≈۳٫۲٪ |
| عکس ردشده | ۱ از ۶۰ | ۳ از ۶۰ | ۳۱ از ۶۰ |

این اعداد مصنوعی‌اند و تخمینی از دقت واقعی نیستند. جزئیات: [docs/benchmarks.md](docs/benchmarks.md).

## حریم خصوصی

تصویر کارت داده‌ی بسیار حساس است. نگهداری فقط با درخواست صریح و رمزنگاری‌شده انجام می‌شود، مدت نگهداری کوتاه باشد، رضایت کاربر را بگیرید و قوانین حفاظت داده‌ی مربوط را بررسی کنید (این متن توصیه‌ی حقوقی نیست). هرگز عکس واقعی کارت را در مخزن نگذارید؛ از مولد مصنوعی استفاده کنید.
